# DSH 上下文管理

自家插件不再限制 DSH 宿主版本号；运行时按实际接口能力工作。开发依赖版本用于复现构建，不是安装门槛。本轮验证基线为 0.2.0-rc.1 与 0.2.0-rc.2，其他版本尚未验证。

DSH 当前包名：`@missher/dsh-context-manager`。2026-09-29 统一命名；仓库与源码目录、配置键及数据目录保持原有值。旧包升级需替换旧依赖与 Bundle 引用，不应同时启用新旧包。

面向 **DeepSeek Harness 0.2.0-rc.1 / 0.2.0-rc.2** 的独立 Bundle，当前本地升级候选为 **0.6.0-local.1**。在会话原有的 **对话 / 轨迹** 后增加 **上下文** 页签；**设置 → 上下文管理** 只放压缩参数。源码参考目标与预设文件摘要见 `COMPATIBILITY.json`。新版验证记录见 [RESULTS-V2-20261001.json](./verification/RESULTS-V2-20261001.json)。

上下文页采用选定的 C 版紧凑单面板布局：顶部展示当前组成与请求指标，中间并排展示“占用变化 / 压缩前后 / 本会话累计”，底部是“当前有效内容”的列表与正文。占用变化采用柱状图，累计用量采用分类条和缓存环图；组成提供四种内容颜色、Token 数和合计 100% 的占比。内容首次进入、重新打开及切换会话时默认展开；本次访问中手动收起后，普通刷新保持收起。默认显示 4 项内容和最近 2 条压缩记录，可继续展开。正文只读取选中条目的当前段落，列表和正文继续分页，不预加载所有历史。仍只有外层“对话 / 轨迹 / 上下文”页签。

当前源码和版本以本目录 `package.json` 为准。首次克隆需先构建宿主，再构建本插件；源码中的 `lib` 不随 Git 分发。统一入口见[插件目录](https://github.com/Missher12/Deepseek-harness-Cordis/blob/main/plugins/README.zh.md)。

升级验证使用独立构建目录，执行 `node scripts/link-harness.mjs /path/to/built-harness` 接入已构建的同版本 SDK，再运行 `npm run build`、`npm run typecheck` 和 `npm test`。脚本只写插件自身的依赖链接，包含 React 开发类型；检查精确宿主版本、刷新旧 SDK 链接，不修改宿主或根 lockfile。运行时仍通过正常 Bundle 版本检查，不增加兼容包或版本豁免。

“上下文”是只读页面，选中时隐藏该会话视图的发送区；切回对话恢复输入框与未发送草稿。使用宿主控件、主题变量及组件归属标记，不依赖或修改 Session Bridge，不操作会话标识菜单；所有旧版交付保留原字节。

当前宿主没有按视图隐藏输入区的选项，因此仅在本视图挂载期间，通过该会话祖先的 `data-conversation-content` / `data-composer-seat` 标记隐藏其常驻输入区，并于卸载时恢复原状态。不扫描全页面、不清空草稿、不修改公共样式；升级宿主时需核验这些布局标记。
## DeepSeek 官方峰谷提示

选择 DSH 内置 `deepseek-official` 或 `deepseek-account` 路由后，模型选择器旁立即显示“高峰期 / 低谷期”。切换到第三方提供方即隐藏。直接订阅模型选择器的共享目录：包括尚未发送消息的新会话默认模型、已确认的切换结果；不读取上下文占用率，不等首轮回复，也不要求出现百分比。失败或尚未确认的切换保持与选择器当前值一致，不发起额外请求。

按 [DeepSeek 官方价格规则](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)（2026-09-29 核验），北京时间周一至周五 09:00–12:00、14:00–18:00 为高峰；其他时间、周末和中国法定节假日为低谷，低谷价格为高峰的一半。点击时段打开原地价格浮层：展示所选模型的峰谷单价、下次切换时间，并可输入同一组缓存命中输入、未命中输入和输出 Token 比较两种时段费用。输入默认留空；未知模型明确显示价格未收录。Escape、外部点击或关闭按钮可收起，官方说明需点击浮层中的链接才打开。按分钟边界刷新，并在页面重新可见或聚焦时校正，与设备时区无关。

2026 年节假日按 [国务院办公厅通知](https://www.gov.cn/zhengce/zhengceku/202511/content_7047091.htm) 的放假日期处理，周末调休上班仍按官方周末规则显示低谷；未覆盖年份显示“时段待核对”，不猜测日历。Flash（含 `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 别名）的高峰价格为 0.04 / 2 / 8 元每百万 Token，Pro 为 0.30 / 9 / 27 元；依次为缓存输入、未命中输入、输出，低谷均为一半。同等用量估算不是实际账单，不回溯计算历史费用；不探测用户对内置官方路由的自定义代理或重定向费用。价格政策或新年日历变化需要更新规则快照。

## 从旧版升级

在单独安排安装时，通过 DSH 插件页选择对应的独立文件夹或 `.tgz`。安装完成后，等当前任务结束，**完整退出并重新打开 DSH**，再检查插件详情显示 **所选包的版本，3 个组件运行中**。打开一个会话，点击“轨迹”后的“上下文”。只关闭窗口、刷新页面或开关插件不能替代进程重启。安装状态以目标 profile 的插件详情为准。

已在用户安装的 Desktop 0.1.7-rc.2 / Node 24.18.1 运行时复现：0.2.1 卸载后，在同一进程安装并启用 0.3.x，Node 仍使用旧包的 `exports` 缓存，导致新增 `./inspector` 报 `ERR_PACKAGE_PATH_NOT_EXPORTED`，界面只显示 `failed to import`。全新进程读取新的导出表后可以启动。升级不会删除会话记录；不需要卸载 Session Bridge 或更换压缩设置。此插件没有修改宿主的全局模块加载器，也不声称热升级缓存问题已由插件修复。

保留原有请求前检查路径，必要时先压缩再执行；0.4.0 新增任务正常结束后的闲置维护路径。采用 Codex 的检查顺序思路，具体摘要、事务与计量继续使用 DSH，不宣称和 Codex 完全相同。

## 图表与内容

采用 C 版单页：当前上下文在顶部；占用变化、压缩前后和本会话累计同组；当前有效内容位于底部，列表与正文并排。窄窗口自动排列，只有“对话 / 轨迹 / 上下文”一层主视图，设置页仅放参数。主图表文案跟随 DSH 的中英文选择，按钮、输入、开关、提示、主题和字体使用原生组件及语义变量。

当前组成以灰色标识压缩摘要、蓝色标识工具结果、绿色标识对话消息、黄色标识指令与定义，显示 Token 数及占比。摘要通过宿主 `compact-checkpoint` 来源识别，仅当前有效的摘要参与组成；已被替换的原文不再计入。点击颜色可筛选底部内容。

默认“有效内容”以分类估算合计为 100%；“整个窗口”以模型窗口为分母并增加剩余空间。内容估算超过窗口时保留超出提示，显示的分段以内容合计为 100%，不伪造负余量。占比显示使用小数位配平，各项合计为 100.0%，Token 数保持原始估算值。没有内容或容量时不绘制假余量。

顶部占用由宿主 `contextPressure` 读取，是提供方输入用量加后续变化估算；颜色组成按内容文本估算，二者不强制相等。图片成本以模型路由为准。压缩释放量仅显示在前后对比，不属于当前摘要的占用。

占用变化用最近 40 个宿主投影截面的柱状图，未知值留空，替换点单独着色。柱高仅来自记录的占用，不补造历史分类。点击柱可查看对应截面的有效内容，并可返回当前。压缩前后显示最近两条记录，可展开全部；比较的是被替换片段，摘要用量和耗时在原生提示中查看。

本会话累计用分段条和缓存命中环展示未命中输入、缓存读取、缓存写入和输出，直接读取宿主 `tokenUsage` 投影。有有效用量记录的失败尝试和重试也会计入；未记录的调用不能补计，独立摘要调用不在该投影中。累计不是当前窗口或实际账单。逐次回复记录同页展开，最多 200 条；历史截面不补造累计。

当前有效内容默认展开，每次先显示 4 项，按需继续显示、分页与读取正文。支持分类、标题/来源检索、顺序、大小排序，以及包含已替换原文。正文每段最多 16,000 字符，图片只显示引用。切换会话和查询会取消旧请求，手动收起不被普通刷新重置；上下文页隐藏当前发送区，回到对话恢复原草稿。

读取使用插件自己的 Typert Remote 和官方 `sessionQuery.observeSession`，释放不可变截面读租约，不激活 Agent、不写日志、不调用模型。分析上限 50,000 条日志，超出明确报错。仅闲置调度状态在面板打开时轻量刷新，完整历史和正文不轮询。

新展示层从所选 HTML 方案实现，未引入研究目录 `dsh-context` 的运行时代码。原请求准入、闲置调度、原生设置和官方模型峰谷入口保持；历史源码、旧安装包及会话日志保留，不随界面更新删除。

## 推荐设置

| 选项 | 默认值 | 含义 |
|---|---:|---|
| 自动压缩 | 开启 | 每次主模型请求前检查，包括工具执行后的下一次请求 |
| 使用到多少时压缩 | 80% | 用户可选 50%–95%，使用 DSH 原生数值设置行 |
| 压缩后希望保留多少 | 55% | 尽量达到的目标，不是精确保留率或无损承诺 |
| 提前检查 | 1% | 在临界点提前腾出空间，因此 79.9% 时提交任务会先压缩 |
| 安全空间 | 2% | 与真实输出预留一起限制有效阈值 |
| 摘要输出上限 | 8192 Token | 同时受模型窗口 10% 和主请求已声明输出上限约束 |
| 每请求最多压缩 | 2 次 | 必须有实际缩减才允许重建；失败不自动重复花费 |
| 单次摘要超时 | 90 秒 | 跟随用户取消和插件停用 |
| 闲置自动压缩 | 开启 | 只在任务正常完成后计时，新消息优先 |
| 闲置时长 | 15 分钟 | 可选 1–1440 分钟，保存后调整已有倒计时 |
| 闲置最低占用 | 65% | 实际门槛不低于目标占用加 10 个百分点 |
| 摘要保留重点 | 空 | 可补充最多 2000 字符；不取消基础摘要约束 |

设置使用宿主 `SettingsForm`、`SettingsValueField`、`Switch`、`Button`，共享原生字号、输入框、边框、主题及保存栏。提供 70%/40%、80%/55%、85%/60% 三组快捷值，以及高级参数。设置先暂存，点击保存后以宿主配置修订号一次提交。界面中的 Token 示例明确标为示例，不冒充当前会话的实时读数。

## 闲置整理

本功能中的闲置指「本次应用运行中观察到任务正常完成，且此后没有新消息」，不根据 Token 回报中断判断。恢复历史或单纯打开上下文页不会开始计时。仅处理已加载且归本引擎管理的会话；应用退出后不运行，不批量扫描历史会话。重新开启开关后从下一次任务正常完成开始计时。

到期后再核验模型窗口、占用、收件箱、任务状态，以及宿主报告的待确认操作、子任务与后台工作。未满足条件则跳过本轮；失败也只尝试一次，直到下一次正常完成任务才重新计时。摘要沿用该会话最近一次实际请求的模型、推理级别，可能产生 Token 费用和缓存重建开销；低于最低占用不调用模型。

闲置整理调用公开 `BasicCompactionEngine.compactNow`，由宿主取得维护互斥并提交摘要与日志，不开启业务任务或伪造用户消息。新消息到达会取消插件自己的摘要操作，保留收件箱并让宿主继续执行；已提交的压缩保持有效，不承诺回滚已落盘的摘要。工具调用配对遵从宿主安全范围。请求前路径保护最新待执行任务原文；闲置路径对宿主允许的历史前缀摘要、保留末尾节点，55% 是软目标，并不保证保留最近整轮原文或精确压到该数值。

上下文单面板中显示倒计时、跳过/失败原因、正在整理和完成后的整段占用变化；此调度状态仅在当前进程内有效。历史压缩记录展示摘要输入/输出 Token（有提供方回报时），被替换片段的前后占用与整段占用分别显示。宿主空闲压缩日志不区分手动和本插件触发，统一标为「会话间压缩」，不虚构历史触发原因。调度状态使用轻量只读 RPC 刷新，不轮询完整历史；退出上下文页即取消。

## 执行方式

1. 宿主接收、记录新任务，确定本次实际 provider/model 和推理级别。
2. `llm/stream` 检查已经组装好的请求，用宿主 TokenMeter 测量输入、系统内容、工具定义和路由相关图像成本。
3. 需要压缩时返回插件专属本地终止码，不调用主模型适配器。`agent/request-error` 接管该状态。
4. 在不破坏工具调用配对、不丢弃最新用户任务的前提下选择历史范围；优先保留最近结果，过大的结果可随完整工具组一起摘要。
5. 摘要沿用本次实际模型和推理级别。复用 BasicCompactionEngine 的事务、替换、缩减检查与原始日志。
6. 摘要成功、日志 flush、确认有进展后，让 AgentLoop 重建请求并重新检查；自动继续，不重复追加任务。

计算口径：`检查线 = min(窗口 × 触发比例, 窗口 - 输出预留 - 安全空间) - 提前检查空间`。输出预留来自请求或适配器默认值；未知窗口明确报错。TokenMeter 可能使用提供方用量或估算值，因此这不是精确分词保证，真实上游溢出仍有同一条有界恢复路径。

本地拦截没有 HTTP 状态，不伪造提供方 413。主模型错误记录与真正的摘要调用分别保留。取消、摘要失败、摘要没有缩减、两次后仍超限时结束当前尝试，用户原文留在原会话；可在该会话发送“继续”或使用宿主的恢复操作。**本版本没有新增跨重启一键恢复按钮或自动恢复任务调度器。**

## 预设与安装边界

Bundle 关闭根 Basic 自动控制器，插入一个根 ContextEngine；Standard、PTC、Cordis 的隔离 compaction group 则各换成同一个派生实现。Minimal 使用根实现。`auto: false` 在构造时确定，不修改已有实例的私有监听器。手动 `/compact` 仍由官方命令与事务实现处理。

当前 Loader 的 patch **按 id 替换整个 config**，不能只替换嵌套 provider 名称。因此 `cordis.patch.yml` 从本次已核验版本的官方预设自动生成，只改变 compaction provider，保留其他字段与条件表达式；原文件 hash 可检查。更新 Harness 后必须重新核对生成。用户已经保存的预设配置属于后置覆盖层，仍然优先；自定义/被覆盖预设需要显式将其 `@deepseek-ai/dsh-compaction-basic` 改为 `@missher/dsh-context-manager/engine`。不声称安装即可接管所有自定义预设。

已运行 Agent 可能仍持有旧预设实例。安装或卸载后按宿主规定重启目标 profile，再验证新实例。插件停用不删除会话数据。
